# 01 · 先把"要点"提炼出来（再动笔写讲义）

写完几十页讲义才发现主线错了，是最常见的浪费。所以先花 15 分钟做一张**要点表**，
它同时是给用户看的大纲、也是你后面写讲义的施工图。

## 输入

- `work/audio.txt`：逐句带时间戳的文字稿
- `work/slides/*.png`：幻灯片帧（文件名 `t00120.png` 里的数字就是秒）
- 原视频/文件的标题、作者、章节号

## 产出（写进 `work/lecture/meta.json` 或一张草表）

```json
{
  "title": "第 9 讲：电路的图与网孔电流法",
  "subtitle": "对应《XX》第 3 章；视频 65 分钟",
  "chapters": [
    {"t": "0:00", "name": "图论复习：什么是图、树、回路", "key": "为后面数方程服务"},
    {"t": "22:20", "name": "网孔电流法", "key": "本讲的主角"},
    {"t": "66:00", "name": "含电流源的讨论", "key": "四个易错点"}
  ],
  "must": ["n、b 怎么数", "为什么方程数 = b", "自阻/互阻的符号"],
  "skip": ["课堂上老师念错卡壳的地方"],
  "unknown": ["两次听不清的具体数值"]
}
```

## 判断"要点"的四条标准

1. **它后面会被用到吗？** 一个概念如果后面再没出现，就不进要点。
2. **它是"方法"还是"名词"？** 方法（怎么列方程、怎么判断是不是树）优先；纯名词定义放讲义的"第 0 节"里带过。
3. **老师反复说的是什么？** 重复 3 次以上的句子，几乎一定是考试点。
4. **哪些地方老师跳过了？** 视频里"这个你们自己看"的部分，标 `skip` 但**不要删**，在讲义里补一句"这里老师跳过了，我补一句"。

## 输出给用户确认

要点表只发**一屏**：章节 + 每章一句话 + 必学/可跳过。让用户确认"重点对不对"再写正文，
比写完 50 页再返工便宜得多。
