# 02 · 写讲义正文（lecture.md）

这是整个项目最关键的一份说明。写出来的是"**能教会一个什么都不会的人**"的讲义，
不是"把视频内容整理成条目"。

## 反面样板（不要这样写）

> ❌ 一、图论基础
> - 图 G 由节点和支路组成
> - 树是连通且无回路的子图
> - 树支数 = n−1，连支数 = b−n+1
> - 方程数 = b

这读起来像复习资料，读三行就困，而且**读者仍然不知道为什么**。

## 正面做法：每一节都回答"为什么"，并且从读者的处境出发

> ✅ 你手上有个电路，不是串并联，没法用分压分流算。怎么办？
> 只有一个办法：设未知数，列方程，解方程。那第一个问题就是——**要设几个未知数？**
> 猜少了算不出来，猜多了方程不够。这一讲就是来回答"到底该设几个、能列几个"的。

三条要求：

1. **每次引入新概念，先给"它要解决什么问题"**，再给定义。定义放在问题后面。
2. **公式必须推一遍。** 不要写"由 KVL 可得 (R1+R2)i1 − R2 i2 = U_S"。要写"从 a 点出发，沿网孔顺时针走一圈，先经过 R1 …（每一步写清方向与正负）… 整理得 …"。读者会推，就永远不会记错符号。
3. **给"手算得出来的例题"。** 参数具体（11 V、2 Ω），步骤完整，最后**用另一条路验算**（节点 KCL / 回路 KVL / 功率平衡）。数字自己先解一遍。

## 结构模板（按需增删，但顺序尽量保留）

```
# 标题（一句话说清这份讲义解决什么问题）
> 对应哪个视频/文件；说明"下面按能不能听懂的顺序讲，不按视频顺序"

## 一、从一个算不出来的问题说起     ← 制造需求
## 二、先把工具备好                 ← 最少必要的定义
## 三、为什么是这样                 ← 推导，最花篇幅
## 四、手把手做一道题               ← 完整解题 + 验算
## 五、换一种情况                   ← 变式（电流源、受控源、非平面…）
## 六、什么时候别用它               ← 边界与代价
## 七、自测 5 题 + 折叠答案          ← 用 <details><summary>答案</summary>
## 最后，一句话记住这一讲
```

## 写作细则

- **口语**：用"我们/你"，短句。句子超过 40 字就断开。
- **术语第一次出现**：中文 + 括号给英文或符号，例如"网孔（mesh）"。
- **符号统一**：全文只用一个符号体系（例如网孔电流 `i1、i2`），别一会 `i_l1` 一会 `I_m1`。
- **表格只用来做对照**（比如"视频说法 vs 教材说法"），不要用表格代替讲述。
- **每节末尾一句话小结**，加粗。
- **图放在它解释的那句话下面**，图注格式固定：`*▲ 视频 mm:ss：这张图在讲什么*` 或 `*▲ 自绘：……*`。
- **不确定的地方**写"（这里原文不清楚，我按上下文理解为……）"，不要静默编造。
- Markdown 里**不要写 LaTeX 公式**（很多阅读器不渲染），用 `i1 = i2 − i3`、`b − n + 1` 这种可直接读的写法。
