# 03 · 写问答库（qa-bank.json）

问答库干两件事：

1. **离线也能答**——没有模型 key、或者断网时，速答框就从这里找答案；
2. **让问题长在讲义旁边**——条目写 `"pin": "三、"`，它就会变成 `## 三、` 下面的一张淡黄便签。

## 格式

```json
[
  {
    "id": "q06",
    "pin": "三、",
    "q": "为什么 b 从 8 变成 6、n 从 5 变成 4？",
    "a": [
      "定义：……",
      "对照：……",
      "规则：……",
      "算式：……",
      "一句话：……"
    ],
    "tags": ["b", "n", "合并", "8", "6", "节点", "支路"]
  }
]
```

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一，`q01` 起顺排；改条目时**不要改 id**（`pin` 只按 id 无关，但日志里靠它） |
| `pin` | 可选。写成讲义里二级标题的前缀，如 `"三、"`、`"十一、"`。不加 `pin` 的条目只在速答框里出现 |
| `q` | 问题本身。用**学生的话**，不用老师的话（"为什么这里要减号"优于"互阻符号规则"） |
| `a` | 答案要点，字符串数组。**按下面五步写** |
| `tags` | 至少 3 个。把同一个意思的多种说法都放进去（`互电阻/互阻/R12`），检索命中率靠它 |
| `open` | 可选 `true`：便签默认展开（给最容易被问住的那一条用，全篇 1–2 个就够） |

## 答案必须按"五步"写

这是用户明确要求的格式，也是唯一能让人真正学会的顺序：

1. **定义** —— 这件事按定义是什么（一句，不带前提假设）。
2. **对照** —— 拿讲义里的**具体对象**逐条对照。比如：
   `支路 3：上端点 A、下端点 C；支路 8：上端点 A、下端点 C —— 起点一样、终点一样。`
3. **规则** —— 由定义得到什么结论，效果是什么：
   `并联合并 → 节点数不变、支路数减 1。`
4. **算式/步骤** —— 把数字代进去，一步一步：
   `b = 8 − 1 − 1 = 6；n = 5 − 1 = 4。`
5. **一句话** —— 让人记住的那一句：
   `并联只少支路，串联才少节点。`

> 禁止的写法：先甩结论（"因为它们是并联的"）、只给公式、给一堆"注意点"但没有对照对象。

## 选题原则

- **从讲义里挑**：每一节挑 1–3 个"这里读者一定会卡住"的地方，别超过 3 个。
- **数量**：整份讲义 30–45 条比较合适。少于 20 条检索太稀；多于 60 条没人维护。
- **"我早就讲过"不是理由**：凡是你会想"这也要问？"的地方，都值得一条。
- **必须覆盖**：全文出现 ≥3 次的概念、所有带符号的规则、所有例题的"下一步为什么这么走"。
- **不确定的不要编**：讲义没讲的（比如更高层的延伸），写成"讲义里没展开，但可以这样理解：…"。

## 抓一个反例自查

如果你写的某条答案读起来像"教科书摘录"，说明它没有 `对照` 和 `算式` 两步——补上再提交。
