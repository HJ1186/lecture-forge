# SECURITY.md · 安全与隐私

这个工具要处理"你的课程、你的笔记、你的模型 key"，所以先把边界说清楚。

## 1. 你的 key 在哪里

- key 只写在 `config.json` 的 `model.api_key` 里，**只在本地 `serve` 进程内使用**。
- key **不会**被写进 `index.html` / `ask.html`（页面只拿到 `{title, api, lang}`），所以你把这个 HTML 发给别人是安全的。
- `config.json` 在 `.gitignore` 里。请不要为了省事把它改名成 `config.example.json` 再提交。
- 如果你曾经把 key 提交过：**先去服务商后台轮换作废**，再清理历史。只在新的提交里删掉那一行是不够的——旧提交里仍然读得到。

## 2. 数据去哪了

| 阶段 | 出网 | 说明 |
| --- | --- | --- |
| ① fetch | 是 | 只有这一步会访问你给的 URL（yt-dlp 下载） |
| ② transcribe | 否 | 本地 Whisper，音频不出机器 |
| ③ slides | 否 | 本地 `av` + `Pillow` |
| ④ 写讲义 | 取决于你 | 用网页版模型写的时候，文字稿会被上传到你选的那家 |
| ⑤ build | 否 | 纯本地渲染 |
| ⑥ audit | 否 | 纯本地正则扫描 |

`serve` 只有在**你点击「问」**时才会把 `{问题 + 当前章节正文（≤2200 字）}` 发给你配置的模型服务。
它不会上传整份讲义，也不会保存对话历史（日志只在需要时开，见下）。

## 3. 本地服务的安全边界

- 默认只听 `127.0.0.1`，局域网里其他机器访问不到。
- 静态文件路由做了目录穿越检查（`..` 会 403）。
- `Access-Control-Allow-Origin: *` 是为了让用 `file://` 打开的页面也能调它——代价是同机上的任何网页都能调用这个端口。
  在共享机器上，建议改成固定来源，或者干脆只用 `serve` 打开页面（同源就不需要 `*`）。
- 不想让它继续跑，`Ctrl+C`。

## 4. 我会不会偷偷上传东西

不会。整个项目只有一个地方发起外部请求：`serve.py` 的 `_call_model`，目标就是 `config.json` 里的 `base_url`；
以及 `fetch_media.py` 里你指定的 URL。没有埋点、没有统计、没有第三方 CDN（页面里的 CSS/JS 全部内联）。

## 5. 发布你自己做的讲义前

一定要跑：

```bash
python -m lecture_forge audit .
```

它会检查密码/token、个人隐私、本地绝对路径、临时文件、构建垃圾、不宜公开的内容。
详见 `docs/AUDIT.md`。**版权同样重要**：从课程视频里截的图、教材扫描页，
只适合自己学；要公开发布，先确认你有权传播，否则只放自己画的图。
